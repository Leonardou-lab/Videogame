# The Coward King

The Coward King is a medieval pixel-art tactical survival game played on an 8x8 board. The player protects King Aldric with cards, allies, defenses, political effects, and careful movement while surviving three levels of escalating hordes and bosses.

## Main Entry Points

- Open `Videogame/indexMenu.html` through a local web server to enter the menu.
- `Start Game` opens `Videogame/index.html`.
- The frontend expects the API at `http://localhost:3000`.
- The game can use an 8-card fallback pool when the API is unavailable, but login, SQL statistics, persistent upgrades, and the full 15-card pool require the backend and MySQL.

## Installation Process

### Prerequisites

Install:

- Node.js and npm
- MySQL Community Server
- MySQL Workbench or another MySQL client
- A modern browser
- Python 3, or the Visual Studio Code Live Server extension

### 1. Clone the repository

```bash
git clone https://github.com/Leonardou-lab/Videogame.git
cd Videogame
```

### 2. Create the database

1. Start MySQL Server.
2. Open MySQL Workbench.
3. Open `Videogame/Database/coward_king.sql`.
4. Execute the complete script.

The script recreates the `coward_king` database and inserts the project data.

> Warning: it begins with `DROP DATABASE IF EXISTS coward_king`; rerunning it deletes the existing local database and its data.

### 3. Configure MySQL credentials

Open `Videogame/Database/server.js` and set the local MySQL user and password:

```javascript
const pool = mysql.createPool({
    host: '127.0.0.1',
    user: 'root',
    password: 'YOUR_MYSQL_PASSWORD',
    database: 'coward_king',
}).promise();
```

Do not use a game account password here. These are the credentials of the local MySQL installation.

### 4. Install and run the API

From the repository root:

```bash
cd Videogame/Database
npm install
npm start
```

Keep this terminal running. The server should report:

```text
API running on http://localhost:3000
```

Verify the API by opening:

```text
http://localhost:3000/api/cards
```

It should return the card list as JSON.

### 5. Run the frontend

Open another terminal in the repository root:

```bash
python3 -m http.server 5500
```

Then visit:

```text
http://localhost:5500/Videogame/indexMenu.html
```

Opening the HTML directly with a `file://` URL is not recommended because browser security rules can interfere with fetch requests, audio, and local asset loading.

### 6. Create a player account

1. Select **Login** from the main menu.
2. Enter a username and password.
3. Select **Sign Up**.
4. Log in with the same account.

The MySQL root account and the in-game player account are separate.

## Verification Checklist

- The menu appears at `indexMenu.html`.
- Music begins after the first browser interaction.
- `Start Game` opens the 8x8 board.
- `http://localhost:3000/api/cards` returns 15 cards when SQL and the API are active.
- Login creates or retrieves a player.
- Statistics and upgrades load for a logged-in player.
- Level backgrounds, sprites, card images, music, and sound effects load without 404 errors.

## Troubleshooting

- **`Access denied for user`:** correct the MySQL credentials in `Database/server.js`.
- **`Unknown database 'coward_king'`:** execute `Database/coward_king.sql`.
- **`ECONNREFUSED` or API unavailable:** confirm that `npm start` is still running in `Videogame/Database`.
- **Cards endpoint returns an error:** check the API terminal and confirm MySQL Server is running.
- **Login says player not found:** use **Sign Up** before attempting to log in.
- **Music is silent at first:** interact with the page once; browsers block audio autoplay.
- **Only 8 cards appear:** the game is using the local fallback pool because the API or database did not load.

## Current Save Limitation

The pause-menu button stores a partial snapshot in browser `localStorage`, while the API records users, runs, statistics, and upgrades. Complete reconstruction of an interrupted board state is not implemented yet, so the current save should not be described as a full Resume Game system.
